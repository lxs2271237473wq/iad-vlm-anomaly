# 新起点：SuperADD受控适配

选择理由：已有AD2公开与私有测试报告及官方代码，比继续试未验证的小模块更适合建立实际效果基线。论文报告的分割F1为public 62.61%、private 57.42%、private-mixed 54.35%；这些不是本项目复现值，不能与A9的AU-PRO比较。

官方源码已下载并部署至orbitad/third_party/SuperADD，commit 44cf25144442fbbc1334ea59d1632327a4376d1a。未修改既有A0–A9实验。

官方采用DINOv3-H+/16、4层特征、640切片、128重叠、0.625缩放、正常增强与memory子采样。服务器仅缓存DINOv3-B；完整H+复现尚未准备就绪。官方依赖声明也与现有环境不同，不能直接覆盖全局环境安装。

## 已完成的执行验证

- 从官方代码加载PreProcessing和PatchedExecution，保留其切片与拼接逻辑。
- 使用现有timm DINOv3-B，在第2、5、8、11层提取未额外归一化的中间特征；这是B骨干适配，非官方H+复现。
- patch batch=1，混合精度，在can和wallplugs各1张正常训练图通过前向。
- 输出4层特征网格分别为40×87及80×95，全部有限。
- PyTorch峰值分配显存分别约0.67GB和0.97GB；仅是这两张图的冒烟规模，不是完整memory评估峰值。
- 小样本分块NN与完整距离矩阵误差分别约8.68e-5、7.63e-6，通过设定容差。尚未实现全量官方子采样的分块替换。
- 首次运行因timm与官方骨干API不同失败，已改为forward_intermediates并成功重跑；该兼容修改局限在独立验证脚本。

## 下一步应运行的准确率对照

1. 当前PCA16：保留既有强基线。
2. 同一B骨干、同容量memory的完整图多层NN：区分层级特征收益。
3. 同一B骨干、同容量memory的重叠切片多层NN：区分空间采样收益。
4. 官方风格正常增强/覆盖子采样：逐项记录新增资源与收益。

正常训练和阈值估计分离；全部类别共享配置，不根据public类别分数分别选模型。首先统一原生GT评估及AU-PRO@0.05/像素AP，再分析tiny召回；论文F1按相同阈值协议另报。固定100000 memory和完整距离矩阵可能引起显存问题，需分块NN及子采样容量预检，不能照搬冒烟峰值估计全量成本。

## 创新研究的进入条件

成熟方法适配只提供效果基线，不算原创成果。只有高分辨率多层对照确实提升真实微小缺陷召回后，才研究在更低计算预算保留这些收益的策略。必须超过均匀切片、简单低分辨率分数路由，实际测端到端耗时和显存；之前全1024地图离线替换的失败结果保留，不能视为尚未研究过的全新方向。

若B适配没有收益，应先分清与官方H+、子采样和评估协议的差异，不能直接宣告SuperADD无效，也不能把作者成绩当成本地效果。

当前状态：技术路径冒烟通过；准确率全量实验未开始；尚未找到经本项目数据验证的新方法。不能保证发表或保证每次实验提升。
