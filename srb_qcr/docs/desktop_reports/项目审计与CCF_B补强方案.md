审计日期：2026-09-09。审计版本：[GitHub 提交 5430d9710b3b0431a93ba1c353a38a33ad804fff](https://github.com/lxs2271237473wq/iad-vlm-anomaly/commit/5430d9710b3b0431a93ba1c353a38a33ad804fff)，提交日期为 2026-07-26。

**3. P0 首先修复可复现性与评测问题**

**3.1 提交的 D5 裁剪路径与现存输出不一致，已实际复现**

Stage 22-D5 的 `load_boxes()` 读取候选 CSV 的原图像素坐标 `x1/y1/x2/y2`。它复用的 Stage 7 `crop_candidate()` 先将图像缩放到 224×224，再直接使用传入坐标。

具体实例：bottle 的候选 CSV 第 2 行原图为 900×900，框为 `(699,357,792,551)`，异常图对应框为 `(174,89,197,137)`。把前一组坐标传给提交的函数会产生右边界小于左边界的 PIL 错误。在该 bottle CSV 的 140 个有效候选上，隔离运行有 123 个触发 `ValueError`；而已保存 CLIP 结果存在正常分数。

因此可以确定“当前提交的这条执行路径不能原样生成现存结果”。不能据此断定历史实验全部使用了错误裁剪，历史运行可能用了未提交的修订代码。

代码证据：[D5 传递坐标](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/experiments/stage22_selective_qcr/run_stage22_d5_mvtec15_clip_crop_reasoning.py#L169)，[Stage 7 裁剪函数](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/experiments/stage7_generalization/visa_binary_prompt_reasoning.py#L172)。

解决方案：统一候选框格式，显式记录坐标空间、图像尺寸及右下边界是否开区间；让离线评分与选择性执行共享唯一的裁剪函数。用角点、边缘缺陷、非正方图和真实候选做几何回归验证，再重跑受影响的 CLIP、融合和统计结果。

**3.2 中心裁剪逆变换需要修正**

检测器明确设置 resize 256×256 后 center crop 224×224；D4b 却将异常图坐标直接按原图尺寸缩放，缺少中心裁剪的偏移。后来的 D6c 改为使用 map 坐标，可缓解 D5 的越界问题，但它复用的裁剪函数仍将整张原图 resize 到 224，不能等同检测器看到的中心区域。

正确做法之一是直接在与检测器完全相同的中心裁剪视图上裁 ROI；另一种是完整记录逆变换，把 map 框先还原到 256 视图（包括 16 像素偏移），再还原到原图。可视化叠加确认后再运行。现有 CLIP-only 表现较弱可能与输入质量有关，但本次没有证明它是低分的全部原因。[预处理源码](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/experiments/stage22_selective_qcr/run_stage22_d4b_mvtec15_patchcore_candidates.py#L315)

Stage 20 将 AnomalyCLIP 的 0.5390 与 LOCO 融合 0.8210 直接比较，并得到 +0.2820。既然图像集合不一致，这个差值不能作为同集公平优势；标注“特定协议”也不能修复集合不一致。现有 AnomalyCLIP 资产主要是汇总结果，不能直接从表格恢复 243 张同集预测。[AnomalyCLIP 数据清单](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/docs/stage20_anomalyclip_baseline/stage20_c2_ad2four_meta_report.md)，[比较报告](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/docs/stage20_anomalyclip_baseline/stage20_d_anomalyclip_ad2four_report.md)

解决方案：生成唯一的评测 manifest，使用 `image_id + SHA256 + label + split`，所有方法严格读取同一清单。优先重新运行全部方法于完整公开测试集，而不是继续追加不同数据子集的汇总分数。评测器断言图像 ID 集合和标签完全一致；对零样本、使用目标正常图像、使用源域异常监督等制度另外标注。

**3.4 选择性执行仍依赖全量历史 VLM 统计，不能直接证明冷启动部署**

D6c 的 `normalize_runtime_m()` 从整份 `base.M_raw` 计算每个目标类别的 min/max，再归一化选择性运行分数。也就是说，当前选择性重放依赖事先已获得的目标全量 VLM 分数统计。这个问题不同于直接读取目标标签，但影响“第一次遇到这批新图，只运行部分 VLM 就得到同样输出”的主张。[归一化源码](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/experiments/stage22_selective_qcr/run_stage22_d6c_mvtec15_actual_selective_runtime.py#L888)

解决方案：用独立源域/正常校准集拟合并冻结 D/M/Q 的尺度映射；明确是否允许无标签目标校准及其样本量、调用成本。对于真正在线方案，只能使用当前及过去允许访问的数据，报告冷启动和稳态成本。不要从待测样本的完整 VLM 结果计算归一化参数。建议采用固定的稳健尺度映射，避免极值归一化或过度裁剪造成饱和及排序并列。

**3.5 `same_as_test` 与默认后处理存在标签使用风险，需要原环境核验**

D4b 设置 `val_split_mode="same_as_test"`，调用 `engine.fit()`，构建 PatchCore 时未显式禁用后处理，导出的是 `pred_score`。Anomalib 的官方说明指出，默认后处理可能利用验证标签寻找最佳 F1 阈值，并将该阈值用于分数归一化。于是，“候选提取函数没有读 GT”不足以证明其上游分数完全不受目标标签影响。[仓库配置](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/experiments/stage22_selective_qcr/run_stage22_d4b_mvtec15_patchcore_candidates.py#L301)，[Anomalib 官方后处理说明](https://anomalib.readthedocs.io/en/v2.0.0/markdown/guides/how_to/models/post_processor.html)

这是需要按实际 Anomalib 版本和 checkpoint 状态确认的风险，本次未在原 GPU 环境证明所有历史分数都受标签影响。应导出原始、未按测试标签归一化的分数，检查验证回调、阈值状态及 clipping；使用独立校准划分并记录每个统计量来源。即使某种单调归一化保持单检测器 AUROC，它仍可能改变多源融合、一致性和门控行为。

**3.6 AD2 的准确率与运行耗时尚未来自同一可重放配置**

Stage 23 已坦诚记录：243 行里有 242 行重新运行的 raw M 与历史值相差超过 1e−4，最大差异 0.02693，原提示元数据未完整保存。这能支持“这些调用确实执行过、跳过调用可以省时间”，但尚不能证明当前实际运行的系统同时取得历史缓存中的准确率。[Stage 23 备忘录](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/docs/stage23_ad2_mirror/stage23_ad2_phase_memo.md)

解决方案：固定新的提示、权重、裁剪资产和代码版本，一次执行同时产出准确率、门控、逐样本分数和耗时。新结果如下降也要接受；历史缓存保留作探索性记录，不能放宽数值容差来宣称复现成功。

**4. P1 最终方法必须战胜更简单的解释**

本次在所有缓存上统一测试固定权重列表 `{0.01,0.05,0.10,0.15,0.25,0.35}`，同时检查使用原 SRB 预门控、门内直接固定权重的版本。没有为每个目标数据集分别选择最佳参数。以下展示 0.10 这一诊断点，完整列表随报告提供：

| 数据 | 原 SRB | 所有图像固定融合 0.10 | 同一预门控＋固定融合 0.10 |
|---|---:|---:|---:|
| VisA / PatchCore | 0.920229 | 0.933211 | 0.925038 |
| VisA / FastFlow | 0.898513 | 0.913338 | 0.899430 |
| AD2 四类 | 0.793922 | 0.791176 | 0.791948 |
| MVTec AD 十五类 | 0.988478 | 0.988478 | 0.988753 |

全部为 macro AUROC。固定全量融合需要更多调用，不能仅按分数认定它更好；“相同预门控＋固定权重”的逻辑调用数与原方法一致，因而是更直接的组件对照。

这些是事后缓存诊断，尚无新的独立测试和配对显著性结论，也受前述数据/实现问题影响。它们足以表明：当前证据不能排除“主要收益来自减小 VLM 权重”，必须补齐小权重、相同门控及相同预算的对照。不能把这张表当作另一种方法已经获证实的优越性。

在该固定列表上，源 VisA PatchCore 的 LOCO 倾向选较大的 0.35；它迁移到 MVTec 后会下降。这提供了一个有价值的研究问题：源域最优的融合强度无法直接泛化。但 SRB 仍要与源域风险约束选参、保守固定融合等方法比较，而不是只比较 0.5 平均。

必须加入的对照分成两组，避免同时改变多个因素：

| 要隔离的问题 | 最小对照 |
|---|---|
| VLM 是否值得调用 | detector-only、廉价视觉复核器、crop VLM、全量融合 |
| 预门控是否选对图像 | 同预算随机选、检测器不确定性选、仅 Q 排序、完整预门控 |
| 自适应权重是否必要 | 同一 gate 下固定小权重、仅 Q、仅一致性、Q×一致性 |
| 弱分支是否制造了需求 | 修正裁剪前后、统一提示；增加一个更强视觉语言分支 |
| 泛化是否依赖宿主 | PatchCore、FastFlow，加一个更强现代检测器 |

对于不同选择器，预算同时按图像调用数、crop 数及实际运行时间报告。每张图的 crop 数不同，“相同调用次数”不一定意味着相同计算量。随机策略至少多次固定种子，并使用相同分数校准、相同融合器。

**5. 统计结论和措辞应收紧**

MVTec 的 SRB−检测器差值为 +0.000265，配对 Bootstrap 95% CI 为 [−0.000870, +0.001414]。在仓库预设的 −0.002 非劣边界下，它支持该设置的非劣性，但不支持显著更优。AD2 对应区间约为 [−0.0066, +0.0241]，下界低于 −0.002，因此连同一容忍界的非劣性也未得到支持。AD2 的正点估计不等于已证明可靠增强。[MVTec 报告](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/docs/stage22_selective_qcr/stage22_d6b_mvtec15_srb_qcr_transfer.md)，[AD2 报告](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/docs/stage23_ad2_mirror/stage23_b1_ad2_frozen_mirror.md)

需要统一修正：

- 主指标统一为 category macro AUROC，pooled AUROC 单列；所有 Bootstrap 与其点估计采用同一聚合方式。
- 测试集最佳 F1 标明是阈值上界诊断；部署 F1、误报和漏报使用独立校准集冻结的阈值。
- Bootstrap 应以独立图像/物件为重采样单位；若存在同一实物多视角、多光照，按物件或场景分组。图像重采样不能代替重新训练或 coreset 随机性验证。
- 使用原始未四舍五入预测计算差值和置信区间；不要把有限次 Bootstrap 的零尾部计数写成精确 `p=0`。
- 解释 0.002 非劣界对应什么使用需求；它不是任意数据集上的安全保证。
- 最终中英文表7把 crop CLIP AUROC 写成 0.555538，而原 CSV 为 0.558553754，应由统一脚本重新生成所有表格以防转录错误。

**6. “有界”“校准”“效率”需要与实际证据对应**

当前公式为：

`A = max(1 − |D−M|/τ, 0)`

`S = D + wmax × G × Q × A × (M−D)`

`G=0` 时严格返回 D 是明确的代数和执行性质。但是分数移动小，不保证正负样本排序不变，不保证 AUROC 不下降，也不保证低误报率下不漏检。“校准”目前主要是启发式分数加权，不应暗示已经完成概率校准或统计风险控制。若采用概率校准措辞，需要相应定义、Brier/ECE 等证据；否则称为可靠性加权更准确。

一个可以发展、但尚不能当作强原创理论的分析是：令 t=|M−D|，则 `|S−D|≤wmax×G×Q×τ/4`。冻结参数下为 `0.065625×G×Q`。若一个原本排序正确的正负样本对满足 `D正−D负 > r正+r负`，其排序不会被这次修正翻转。这比宽泛地称“安全”更精确，也能据此分析脆弱样本对和失误机制。但源域经验界不能在没有分布假设时变成目标域 AUROC 保证。

运行报告的 21.21% 节省主要覆盖 VLM 图像读取、裁剪、预处理和推理阶段，检测器、候选生成和部分准备工作不在同一计时窗口。因此中文摘要中的“端到端时间减少”需改正，或补真正端到端计时。AD2 同理。[MVTec 计时范围](https://github.com/lxs2271237473wq/iad-vlm-anomaly/blob/5430d9710b3b0431a93ba1c353a38a33ad804fff/docs/stage22_selective_qcr/stage22_d6c_mvtec15_actual_selective_runtime.md)

真正要回答的是：相对 detector-only 多花的成本获得了多少必要收益；相对全量 detector+VLM，在相近性能下节省多少成本。两个比较对象不能混用。按阶段计时并报告总时延、吞吐、p50/p95、crop 编码数和峰值显存；区分校准准备与稳态推理。对 CLIP 这种可批处理模型，还应比较合理批量大小，避免只在低效逐图循环上展示加速。

**7. 建议收敛成一个更有发表价值的研究问题**

建议主问题表述为：**在不使用目标域异常标签的条件下，如何判断局部视觉语言复核能否纠正当前检测器，并在计算预算和误判风险约束下使用这些证据。**

当前 Q 多由异常响应强度构造，它并不天然等于“VLM 会答对”或“复核能帮忙”。高 Q 可能只是检测器已经十分确信；低 Q 也可能包含检测器漏掉而 VLM 能发现的缺陷。一致性抑制还可能拒绝最有价值的纠错样本。因此建议把质量估计推进到“预期复核收益”，而不是继续叠加一个命名更复杂的乘法项。

可实现的方向是：先用不依赖目标标签的廉价特征描述 detector uncertainty、候选区域相对背景的异常对比、候选跨尺度/轻微扰动稳定性、不同特征层响应一致性；在源域开发类别上，利用折外预测估计哪些特征能预测纠错/伤害，再在预算内选择复核。融合阶段使用独立校准后的证据和保守修正规则。

如果加入由源域异常标签训练的轻量门控，必须明确是“无目标域异常监督”，不能再称整个流程纯训练自由。若坚持不训练门控，则预先固定代理指标，靠源域开发和独立迁移验证其价值，不能按目标成绩反复翻转 Q 方向。

应统计四种真实行为：检测器正确/VLM正确、检测器正确/VLM错误、检测器错误/VLM正确、二者都错；比较门控接受率、修正成功率、引入错误率和遗漏的纠错机会。这里的正误需基于独立校准阈值，或使用明确的排序收益定义，不能直接把归一化分数0.5当已验证的决策阈值。

如果修复后 VLM 并不能带来超过廉价视觉复核器的收益，应接受这个结果并更换研究切入点；仅靠把融合权重压到接近零，难以支撑具有实质贡献的增强方法论文。

最终稿的参考文献主要停留在较早期检测器和 CLIP 基线，对选择性推理/路由也缺乏必要引用。至少核查以下直接相关工作，训练制度、任务和输入信息不同的论文不能简单复制数值放入同一榜单：

**9. 最小补强实验包与执行顺序**

这是一份工作量安排，不是保证完成时间。现有服务器、权重和图像都可用时，可按约六至八周规划；前两周用于判断是否值得继续该方法路线。

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| 第一步 | 固定环境、manifest、预处理及裁剪变换；排查验证后处理标签依赖 | 从干净环境可执行；框位置正确；所有方法图像集合一致；统计来源明确 |
| 第二步 | 同一配置重跑检测器/crop/VLM/融合；准确率与耗时共同导出 | 不再靠两组无法数值对应的缓存证明同一个系统 |
| 第三步 | 同预算简单选择器与固定小权重消融 | 判断复杂 Q×agreement 是否有独立贡献 |
| 第四步 | 在源域选方法/校准参数，然后冻结；增加独立未参与设计的验证 | 避免在已查看目标上继续调参却仍称严格未见测试 |
| 第五步 | 完整 MVTec AD、VisA，加完整 AD2 公开八类或新的困难数据 | 至少一个困难设置中看到有意义的纠错价值；报告负迁移 |
| 第六步 | 强检测器宿主、第二个 VLM 分支、运行成本曲线 | 证明收益不只依赖一套较弱 CLIP 输入或单一检测器 |
| 第七步 | 图像/物件级配对统计、适当的独立随机运行、真实部署阈值 | 主差值及区间稳定，指标与部署主张对应 |
| 第八步 | 单一主方法、统一结果表、精简写作 | 每个主贡献都由最终方法的直接实验支持 |

预算曲线可预设为 0%、10%、25%、50%、75%、100%，横轴同时给实际毫秒/crop 编码数，纵轴给 macro AUROC、AP，以及固定误报约束下的召回。预算为0就是 detector-only，不可从图中省略。25%是“调用比例”还是“节省比例”必须始终明确。

AD2 官方具有八个场景，公开测试只是较小的带标注部分，更大的私有测试由官方服务器评估。因此现有四类243图只能作为局部研究协议，不能代表完整 AD2 基准。[MVTec AD 2 官方说明](https://www.mvtec.com/research-teaching/datasets/mvtec-ad-2)

建议优先完整公开八类，并按光照/类别展示失败边界。若论文仍聚焦图像级识别，应先核对官方服务器接收的输出与返回指标，不能把只改善图像分数的方法包装成像素定位提升。MVTec LOCO AD 的逻辑异常可作为语义互补扩展，但可能需要全局上下文分支，不能假设局部高响应裁剪天然覆盖逻辑异常。

目前已有的目标结果已被用于研究分析。后续根据这些结果修改方法，应把它们归入开发证据，再保留新的未使用类别/数据集/私有测试作最终验证；只冻结一个 JSON 文件不能消除此前方法设计时已经看到的目标反馈。

**10. 投稿前应达到什么状态**

以下是建议的内部停止条件，不是会议官方录用标准：

1. 代码、模型、提示、变换、manifest 和论文数字能够逐项对应；不存在当前 D5 的源码/结果矛盾。
2. 全部主表同集、同指标、同监督设置；新的 SRB 与外部基线直接比较，不借用旧方法最高结果。
3. 相同预算下优于随机、检测器不确定性及保守固定融合中的强对照，且优势不只是一两个挑选的案例。
4. 至少一个困难的独立目标上，额外视觉语言计算带来实际可解释的收益；强检测器场景中的退化幅度受到检验。
5. 可靠性主张有直接的伤害率、纠错率、排序或统计证据，效率主张有包含校准成本说明的真实运行依据。
6. 与最接近的2025–2026工作有清楚的方法差异，论文可以由一个研究问题、一个核心机制和少量必要表格讲清。

不要先给自己规定“必须提升2个点”等任意指标门槛。审稿更关心贡献是否独立、比较是否公平、效应是否可信以及结论是否适用于重要场景。

**11. CCF B 会议定位**

已核查 CCF 2026 第七版官方目录。ICME、ICMR、ICASSP、ECCV 均为 B；BMVC、ACCV、ICPR、IJCNN 为 C；WACV 未列入该版目录，不能用作满足最低 B 要求的兜底。目录等级也不意味着 ECCV 容易投稿。[CCF 官方目录发布页及下载入口](https://www.ccf.org.cn/Academic_Evaluation/By_category/)

对当前题目，建议先按 ICME 正式长文的完整度规划：围绕多模态复核价值、可靠性和计算成本建立统一实验。如果后续正常参考检索与证据选择成为实质算法贡献，可考虑 ICMR。ECCV 虽为目录 B，方法新意和实验深度要求仍很高，应在补强结果明显成立后再评估。

最低 B 的目标应明确为相关主会认可的 Full/Regular 论文；不要把 workshop、short、demo 等自动视为达到同等目录等级。确定目标时核对当届投稿轨道与学校采用的目录版本，不以本报告代替单位认定。
